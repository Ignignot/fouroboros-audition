Method (all clips): writer-produced patterns (real oro_write, game path, plan + card) through the real sequencer (seq_step / seq_ratchets / voice allocator, inside mix_block) and the real SLOOP mix_block DSP, rendered on host at 44100 Hz. Read before listening.
  • p4ord, p6zero, and p6lvl are much quieter (−33, −33, −35 dBFS vs −20 for the rest). Turn the volume up for those three. The quietness is the host-track/trio timbre, not a six-note effect.
  • p6rest sounds identical to p6 (same PCM hash). That is expected, not a duplicate error: in this phrase the chord gate already ended before the REST step, so REST and an empty step both release — and release is what REST does. The REST proof is the contrast with p6tie (sustained) plus the voice logs (REST step: seq empty, voices in release, freed by the next step).
  • REST audio after note-off is release fade + FX tail (reverb/delay), which legitimately sustains ~2 steps at ~30% of chord level before decaying. Stuck notes would sustain indefinitely; these decay to <10% within 2 steps. Voice logs (freed by step 2) prove the notes are off; the tail is FX, not stuck voices.
  • A true mid-write authored fail (goto fail → clear_tracks, same function as the proven pre-clear) is code-reviewed, not separately audio-proven here: triggering it would require corrupting a valid blob in place, which the host harness cannot do without faulting on its own read-only blob data. The reachable fail/fallback paths (every oro_write pre-clear, level change + authored write) are audio-proven below.
  • Still outstanding (not hidden): full run_tests.sh soak; form_bank_v1 line-64 failure is unchanged from base (pre-existing, not a candidate regression); authored card blob format is a separate deliverable (this candidate's six-note steps come from the game path with plan_card).
